## 问题与目标

现有迁移前备份由运维停 API 和 Worker 后执行 `pg_dump` 并复制图片。T68 要保留可读服务，同时阻止新写入和任务领取，确认运行中的工作已退出，再在同一个数据库快照窗口保存数据库、所需图片和版本证据。T69 要验证内容后恢复至新建隔离目标，并撤销旧认证状态、重建派生索引。

数据库和注册图片是备份内容。只读源目录、模型、运行密钥和可重建全文索引由原管理边界处理。隔离恢复完成后由操作者另行决定是否切换实例。

## 备选方案

| 方案 | 权衡 |
|---|---|
| 沿用停服务后备份 | 路径已做过 dev 验收。读请求在停机期间无法服务，退出确认和快照校验仍由操作者完成。 |
| 用数据库锁协调 API、Worker 和命令 | 既有 PostgreSQL 提供进程级互斥，连接断开释放锁。需要逐一接入写入口和 Worker 维护循环，明确在途工作和外部执行的退出条件。 |
| 仅由 PostgreSQL 导出快照 | 对 SQL 数据可获得一致视图。资产登记和对应文件的回收仍需跨资源互斥，数据库视图本身无法约束文件删除。 |

## 推荐方案

1. 使用实例数据库内共享与独占事务级 advisory lock。写操作和 Worker 每次任务或维护批次在开始前尝试共享锁，持有到本次工作及独立异步资产写入结束。备份有界等待独占锁。锁等待期间新写入返回维护错误，Worker 暂停领取和发布；已准入操作继续结束。普通鉴权读取使用无续期读取路径。迁移与外部数据库写入安排在维护窗口之外。
2. 独占后验证不存在未确认的运行或发布。复用现有 Job 租约、持久外部执行退出证明和状态探针；证明缺失或等待超时则退出并释放本次锁。维持原有任务领取和恢复机制。
3. 在同一一致性快照读取资产登记与迁移版本，并用该快照执行 PostgreSQL 自定义格式导出。验证应保留的图像真实存在且摘要与数据库一致。备份目录私有，清单含格式版本、应用版本、迁移状态和各文件长度及 SHA-256。仅完整写入并核对后才发布完成清单，失败目录留作诊断。
4. 恢复先验证可信本地备份的清单及所有摘要，然后使用新数据库与新资产根。命令拒绝已存在的数据库、资产根和运行实例路径。恢复会话、挑战和一次性凭据设为撤销或清空。保留 Passkey 凭据与业务版本、资产引用、聊天快照和历史，再对独立索引重新发布。源目录保持只读。失败目标继续隔离，保留诊断。
5. API、Worker 和管理命令沿用同一锁键。完成运维切换前继续使用已验证的停止本实例写入后备份流程。隔离恢复不触及生产实例。

## 影响与迁移

需要覆盖 HTTP 写路径、会引起会话续期的读取、脱离 HTTP 请求存活的图片上传、同步和异步发布、事务型管理命令及后台回收。锁连接与业务连接需分配独立预算，避免小连接池互相等待。备份失败将由事务或连接结束释放独占锁。隔离目标保留诊断，后续重试选择新的空目标。数据库认证、测试实例编排和应用路径管理沿用既有 ADR。

恢复演练需要独立的全文索引目标。重建时保留引用依赖使用的历史 chunk 和版本标识，按当前有效来源重新发布索引。备份摘要提供完整性校验，备份来源由操作者选择可信的本地产物。

## 验证与开放问题

- 本机 PostgreSQL 18.6 在隔离测试库的三连接探针中，独占锁排队时新的共享申请返回 `false`，独占退出后共享申请恢复为 `true`。该探针只证明本机锁行为。
- T68 应用测试覆盖有在途写入的维护准入、图片缺失、进程退出、独占超时，以及失败时恢复写入。
- T69 在新目标实测摘要错误拒绝激活、旧授权失效、现有 Passkey 重登、历史和引用保留及全文与向量重建。
- 规则 12 要求用户确认此跨进程和备份格式决策。T70 的生产主机接入和上线授权范围另行确认。
