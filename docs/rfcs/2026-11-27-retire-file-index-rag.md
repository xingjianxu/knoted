# RFC: 文件全文索引与 RAG 退出

- Date: 2026-11-27
- Status: Draft
- Owner: Knoted 维护者 Xingjian Xu
- Related issues / ADRs: [#314](https://github.com/xingjianxu/knoted/issues/314)、[ADR 0001](../decisions/0001-machine-level-model-artifact-roots.md)、[ADR 0006](../decisions/0006-file-pipeline-and-aggregate-contracts.md)、[ADR 0007](../decisions/0007-execution-exit-confirmation.md)、[ADR 0011](../decisions/0011-consistent-backup-and-isolated-restore.md)
- Decision record: 维护者已确认功能范围，退出与兼容性契约待单独确认。

## 目标

从主线移除文件正文索引和 RAG。完整的改动前代码、测试、配置及历史迁移已保存在 [archive/file-fulltext-rag](https://github.com/xingjianxu/knoted/tree/archive/file-fulltext-rag)，提交为 `3624a3e8346d4c74b5141a114c676c46479c4717`。文件浏览、原件下载及预览继续使用现有路径，已转存的笔记继续作为普通笔记读取。

## 现状

- `file_extractions` 是文件正文发布的来源。Worker 将提取结果发布到统一全文索引，并构建 RAG 分块、词法与向量索引。下载、预览和 Office 原件授权直接读取已核实的源文件。
- `/search` 同时查找笔记、项目、事项、文件与问答消息。现有问答的生成流程会组装检索上下文，引用和回答转存位于同一功能内。
- `/files/jobs` 与 `/jobs` 同时承载扫描、采集、提取和索引任务。扫描与稳定采集还负责建立可浏览的文件来源。
- SQLx 校验已发布迁移的版本与校验和。`0020` 创建 pgvector 扩展与向量列。现有备份含数据库数据和已登记图片，恢复工具还会撤销旧授权、退休旧任务并重建检索索引。

## 退出方案

| 方法 | 运行影响 | 兼容成本 |
|---|---|---|
| 移除运行路径，继续兼容已发布迁移与备份 | UI、API、Worker 和部署退出已确认下线的能力，相关历史留在数据库 | 核对旧任务、外部副作用和备份兼容，旧迁移链仍要求 PostgreSQL 提供 pgvector |
| 关闭运行开关并继续发布实现 | 调整配置即可恢复使用，相关实现及依赖继续随主线发布 | 升级成本较低，仍需维护索引与 RAG 代码 |
| 同期清理数据库和外部索引数据 | 移除遗留数据库结构及资源 | 需要单独确认数据清理、备份迁移和恢复策略 |

建议选择第一种。在保留的功能范围内复用现有接口和依赖，移除所有已下线能力的新任务提交和读取路径。发布的迁移保持原校验和，历史文件正文、问答及已转存笔记留在备份中。停用进程前确认旧实例已结束对应的租约和外部操作。切换后使待执行的旧任务退出领取和重试路径，同时保留任务记录。隔离恢复继续确认来源和目标隔离，撤销旧授权，并仅为保留的功能重建派生产物。

## 已确认范围

| 功能 | 决定 | 影响 |
|---|---|---|
| 全站搜索 | 保留笔记、项目和事项搜索 | 保留这些对象的 Meilisearch 发布与查询，删除文件和问答命中 |
| 问答 | 下线问答页面、会话 API、引用和回答转存入口 | 现有会话资料留在数据库，已转存的笔记继续可用 |
| 正文提取 | 下线后台文本、PDF、Office 和 OCR 提取 | 源文件预览继续可用。正文提取和嵌入均退出后，Python 执行服务可退出运行编排 |
| 文件任务 | 下线文件任务页和手动扫描接口 | Worker 继续监听文件目录和定期扫描，维持文件列表及预览 |

## 迁移与验证

- 在隔离数据库使用旧版本创建文件来源、积压任务、笔记及备份，再升级并读取。检查已下线的旧任务不会挤占队列、触发外部请求或被公开 API 重试。
- 全站搜索在 Meilisearch 请求和 PostgreSQL 可见性校验中限制对象类型，防止共享旧索引中残留的文件或消息进入搜索结果。
- 开发实例切换时用旧版确认仍在运行的提取、问答和索引操作已退出，再切换 pcwrap 的进程清单和应用配置。恢复也以独立实例为目标。宿主共享模型与原有数据继续保留。
- 保留数据库、模型共享目录、外部索引数据及旧账本。若需要重新启用归档实现，使用匹配的旧运行环境和备份演练，根据当前业务数据重建派生索引。
- 在隔离实例核对文件更新、预览、备份和恢复，验证确认保留的搜索及扫描范围。验证 OpenAPI、客户端、Web 导航与部署配置一致。
