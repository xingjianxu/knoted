## 背景与问题

原有停服务备份用于原实例升级回退。T68 需要在正常读取仍可服务时，让数据库和登记图片对应同一快照。T69 需要验证该备份可以恢复业务数据，同时避免触及原实例的数据库、资产和索引。完整讨论见 [RFC](../rfcs/2026-11-19-t68-t69-consistent-backup.md)。

## 决策内容

- API、Worker 和会写入的管理命令统一使用数据库事务级 advisory lock。写操作、Worker 任务和维护批次在开始前申请共享锁，直至数据库、文件和派生发布的本次工作结束。备份限时申请独占锁，申请排队后新写入返回维护错误，Worker 暂停领取。维护期间读取使用无续期鉴权。锁连接与业务连接分配独立预算。
- 独占后核验 Job 租约、Python 和聊天上游的退出证明，以及相关 Meilisearch 索引的待处理任务。退出无法证明、超时或锁连接失联时终止备份。
- 取得独占锁后，用另一连接开启只读可重复读事务并导出快照。登记资产、迁移记录和 PostgreSQL custom dump 使用同一快照。独占锁保护整个文件复制窗口。归档所有登记为 `ready` 的资产，并核验当前、历史及回收站引用、字节数和 SHA-256。私有目录在全部核验完成后才写入完成清单。清单包含格式版本、应用版本、迁移状态，以及各文件长度和摘要。
- 恢复首先检查可信本地备份的清单和摘要，随后创建空数据库和新资产根，并使用独立的暂存根、Python 账本及 Meilisearch 实例。拒绝现有数据库、资产根及运行实例路径。启动前撤销旧会话、挑战和一次性授权。保留 Passkey、RP ID、业务和引用历史，配置该 RP ID 下专用的 HTTPS origin。冻结恢复来的运行任务与发布记录，接入获授权的只读源，重建独立全文、RAG 词法和向量索引。失败目标保持隔离，保留诊断。
- 首次切换时使用现行停写备份流程，确保运行的 API、Worker 和管理命令采用一致的维护协议。迁移和外部 SQL 写入安排在维护窗口之外。原实例升级回退继续遵循 [ADR 0007](0007-execution-exit-confirmation.md)，保留现场执行账本和退出凭证。T70 生产接入单独确认。

## 备选方案与理由

停服务备份已经验收，适用于升级回退，代价是读取同时中断。仅用 PostgreSQL 快照可以保证数据库一致性，文件回收仍可能删除快照所需的图片。数据库维护锁复用既有事务和断连释放能力，可以在保护文件窗口的同时提供数据库一致视图。独占锁和快照分开取得，确保排队期间已准入操作的提交纳入快照。

## 影响与验证

应用需要覆盖会话续期、异步上传、Worker 周期任务和外部异步发布等写入口。维护期间会暂停新写入与 Worker 处理。备份不含源文件、模型、运行密钥、可重建索引或现场执行文件。失败归档无完成清单，失败恢复目标保留诊断；使用新目标重试。

[T68](../plans/knoted-v1/tasks/T68.md) 验证在途提交、维护拒绝、缺图及失败后的解锁。[T69](../plans/knoted-v1/tasks/T69.md) 验证摘要错误、旧授权失效、Passkey 重登、历史与资产保留及独立索引重建。
