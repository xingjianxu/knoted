## 背景与问题

已发布的 BlockEditor 可以插入和粘贴表格。笔记适配器、Rust 领域层和 OpenAPI 当时的白名单拦截该块，用户看到的表格编辑无法保存。

## 决策

在现行 `NoteDocument` v1 里增加 `table` 块。矩形表格持久化单元格内容、有值的列宽、表头行数和列数。单元格复用笔记的五种行内标记和安全链接契约。合并单元格与颜色、对齐等呈现属性属于本次契约之外的能力。

笔记和历史快照沿用现有 JSONB。全文与 RAG 共用纯文本提取，以制表符分隔列、换行符分隔行，并保留表格块的 ID 和位置。既有笔记块属于现行格式，不需重写。

API、Worker 和 Web 作为同一版本交付，旧版客户端或服务无兼容接口、降级转换或双写。启用表格写入后的回退版本须具备当前契约的读取能力。

## 备选方案与理由

- 将表格转为纯文本可以使用既有存储，但重新打开后无法继续编辑行列。
- 新增 v2 格式需要扩展笔记与快照版本模型，增加部署协调。增加单一表格块可以使用现行格式直接交付。

## 影响与验收

扩展 Rust 校验、OpenAPI、生成客户端和前端适配器。沿用 2 MiB、5000 块及 8 层嵌套的上限，新增最多 1000 行、100 列和每文档 10000 个单元格，列宽以 1 至 10000 像素的整数表示。无效表格应保留已保存正文并给出明确错误。验证范围见[任务卡 #308](../tasks/308.md)。
