# 任务规划

| 复杂度 | 判断 | 必需记录 |
|---|---|---|
| 简单 | 单点修复、少量文档/配置；边界和验证明确 | 会话中说明范围和验收 |
| 中等 | 多个关联文件或独立功能；接口影响可控 | 简要方案、Issue 或计划记录 |
| 复杂 | 核心接口、迁移、跨模块依赖或多个独立交付环节 | brainstorming、writing-plans；`docs/plans/` 持久化计划 |

以依赖和风险判断，不能仅按行数。发现复杂度升级时先更新计划，再扩展实现。

非简单任务优先建立原生 Plan/TODO：分析 → 规划 → 隔离 → 实现 → 测试/审查 → 集成 → 主线验证 → 清理。保持一个主要 in-progress 步骤；pending、in-progress、completed、blocked 的含义由当前工具适配。只有验收证据满足才能 completed。

工具缺失时使用 [计划模板](../plans/template.md) 的状态表与检查项，标明当前步骤、阻塞、证据和时间。不能以工具不可用为由跳过规划，也不能声称文本清单是原生工具。Issue 管长期任务，计划管方案和交接，原生 TODO 管当前进度，三者不替代。

复杂计划必须列出每项任务：输入、输出/文件范围、执行者、依赖、是否可并行、测试命令、验收、风险和人工决策点。只有文件范围和接口独立的写任务才能并行；共享核心文件时改为串行或由主 Agent 集成接口。

Subagent 状态同步到主计划：已派发、实现就绪、审查通过、已集成。子任务报告完成不等于整体完成。计划变更记录原因、影响的验收项和授权依据；业务范围或重要架构变化需人工确认。
