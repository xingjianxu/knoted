# T68–T69 一致性备份与隔离恢复实施计划

依据 [ADR 0011](../decisions/0011-consistent-backup-and-isolated-restore.md)、[T68](knoted-v1/tasks/T68.md) 与 [T69](knoted-v1/tasks/T69.md)。主 Agent 集成并复核，每步仅委派一个实施者，写入各自 Worktree。任务分支经独立评审、本地门禁、PR 普通合并、主线及真实 dev 验收后清理。具体命令和结果回到任务卡及证据文档。

### Task 1: T68 维护准入

- [x] 在 core 提供由数据库标识的共享和独占事务级锁。写及 Worker 批次使用短路共享准入，备份限时等待独占，业务连接与锁连接分别管理。
- [x] 将 API、会话状态、异步资产上传、管理命令、Worker 任务及周期写入接入准入；维护期保留无续期读取，并保持在途工作持锁至结束。
- [x] 验证已准入操作提交、独占排队、写拒绝、读取、脱离请求的上传以及超时释放。

### Task 2: T68 生成备份

- [x] 取得独占后核验本地租约及外部退出和发布条件。第二连接建立只读可重复读快照并保持到 `pg_dump` 结束。
- [x] 同窗口读取迁移信息及登记资产，核验引用与内容，在私有目录最后发布完成清单。
- [x] 以实际 PostgreSQL dump 和资产夹具覆盖 T68 的成功及失败分支。主 Agent 验证首次切换的停写备份及真实 dev 服务。

### Task 3: T69 恢复与演练

- [x] 以已验证的 T68 格式实施恢复。先核验清单，再建立隔离的数据库及资产根。撤销历史认证状态并冻结继承的可执行运行记录。
- [x] 启动独立目标的运行服务，重采集授权来源，重建全文、词法与向量索引，保持历史身份与引用。
- [x] 验证失败隔离、旧会话撤销、Passkey 重登、历史和图片恢复、检索和源实例保持完整。

## 执行约束

开发和验收使用独立 Worktree 与任务数据根。只读源保持只读。数据库、文件和外部发布均须纳入退出条件。源与恢复目标分开，恢复命令拒绝现有数据库、资产根及运行实例路径。生产启用需单独确认。

实际执行记录见 [T68 一致性备份](knoted-v1/evidence/t68-consistent-backup.md) 和 [T69 隔离恢复](knoted-v1/evidence/t69-isolated-restore.md)。
