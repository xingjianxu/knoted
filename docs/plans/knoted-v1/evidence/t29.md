## 接口与归属

直接消费发布版 `@bixlab/mtone@0.3.0` 的公开 `Upload`（upload/signal/retry/cancel）及 `Select`（受控 value、自定义 options）。核对发布包 `dist/index.d.ts:168,750` 与实现并以真实组件验证；属于笔记业务组合，没有通用缺口、上游申请、依赖/锁文件/API/存储变化。遵守 [ADR 0002](../../../decisions/0002-mtone-ui-ownership.md)。

`ImageBlockControls({ client, blockId? })` 和 `CodeBlockControls({ blockId? })` 放在 `NoteEditor` children 中。后续页面须按笔记 ID 为 `NoteEditor` 加 key（原有初始值契约），控制器随编辑器卸载。指定 `blockId` 时替换该图片；未指定时选择文件即捕获光标块，图片替换，其他块在其后插入。只有真实上传返回有效资产 ID 才修改文档，不建立空图片或临时 URL。界面只过滤 PNG/JPEG/WebP，字节解码、大小与权限仍由服务器决定。

上传用生成 `ApiClient.raw.POST('/assets')`、`Idempotency-Key` 和 multipart serializer；fetch 生成 boundary，现有客户端附带 same-origin cookies/CSRF。失败和取消保留旧图；重试使用原 File 的原键/原目标。较新的文件选择取代同目标旧请求；块删除（含删除后撤销）、转型、其他图片替换、组件卸载/目标变更使旧结果失效。API 客户端对象重建不改变逻辑上传身份。新增图前后均检查 5000 块；插入同级无子节点，保留 8 层边界。插入/替换只有一次编辑命令和一次文档变更，可一次撤销。

图片渲染使用原生 `img`，读取 `/api/v1/assets/{encodeURIComponent(assetId)}/content`，持久化仍仅 `asset_id`；图注/语义 shared props 保留。代码保留原生 `<pre><code>`、所有原文和 marks，语言只修改 language prop；预设外的已加载语言作为独立 option 原样可见。仍是 7 种块/5 种 marks，不包含自动保存、正式笔记页或语法高亮。
