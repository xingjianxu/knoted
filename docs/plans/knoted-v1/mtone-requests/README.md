# mtone 通用能力需求记录

本目录存放交给用户、由用户在 mtone 实施的通用能力请求；不是 mtone 实现目录。按 [UI 指南](../../../development/ui-mtone.md) 和 [mtone-component-request Skill](../../../../.agents/skills/mtone-component-request/SKILL.md) 执行。

当前**没有真实已确认的组件缺口请求**。调研发现的分页/时间/焦点检查项，以及 Skill 测试中的模拟缺口，不登记为真实任务。

## 存档约定

- 文件名 `YYYY-MM-DD-<capability>.md`，需求 ID 采用日期与能力短名；在独立任务 Worktree 创建。
- 先查重本目录与关联 Knoted Issue；同一能力补充现有记录，列出所有消费任务。查重失败如实注明，不默认新建重复请求。
- 文件主体保存完整提示词，满足 Skill 七项输出契约；元信息与证据引用可附在提示词之外，但提示词必须能脱离当前会话阅读。
- 文件头部写明元信息：需求 ID、消费任务、上游 Issue 编号与 URL（未创建时写原因，不得虚构）、当前状态。
- 将完整提示词直接发送给用户，不能只给文件路径；同时在 `xingjianxu/mtone` 提交英文 feature Issue（先查重、仅用既有 `enhancement` 标签，不写 Knoted 内部决策与私有数据）。不替用户修改 mtone 源码、代发上游 PR 或发布包。
- 不包含凭据、私有正文或敏感样例，复现用最小公开数据。

## 状态与恢复

| 记录状态 | 证据 |
|---|---|
| 草稿 | 需求与证据已整理；缺失资料或未完成的上游 Issue 已列入待补项 |
| 已交接 | mtone feature Issue 已创建并回写编号/URL，且提示词已实际发给用户（会话/评论记录）；缺任一项不得标此状态 |
| 待发布 | 用户提供上游实现信息，但尚无可消费 npm 版本 |
| 待消费验收 | 已核实 npm 版本可用，等待 Knoted 锁版和测试 |
| 已验证 | 相应消费测试、本地门禁、PR/主线验证及适用部署完成，有提交/PR/结果 |

这是本目录的记录状态，不新增 GitHub Labels/Projects 选项。关联消费任务遇到真实阻塞时使用既有 blocked 标签，保留看板阶段，并列受影响验收及恢复条件；不自动阻塞所有下游或授权并行。正式产品任务完成仍遵守根 AGENTS.md。
