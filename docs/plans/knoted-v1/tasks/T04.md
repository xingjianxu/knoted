- 契约实现：`@knoted/api-client` 为 source-only workspace 包，`exports/types` 指向 `src/index.ts`；`createApiClient({baseUrl, fetch?, onUnauthorized?, csrfCookieName?})` 使用 `openapi-fetch`，所有请求 `credentials: "same-origin"`，非 GET/HEAD 从 `knoted_csrf` cookie 附加 `X-CSRF-Token`（缺失时省略且不抛错），非 2xx 经 `onResponse` 抛出 `ApiRequestError`（可解析 ApiError 时映射 code/message/request_id/field_errors/current_version，否则回退 `code: "http_" + status`、`requestId: ""`、`message: "HTTP " + status`），401 额外调用 `onUnauthorized` 一次且不重试、不跳转。TanStack Query 的 `context.signal` 原样传入 `raw.GET/POST`，取消时 `Request.signal` 中止。
- 查询入口：`apps/web/src/lib/query.ts` 导出 `normalizeFilters`（丢弃 `undefined`/`""` 并排序键）、按实体分组的 `queryKeys`（列表键含规范化过滤，详情/快照/活动键独立）与 `createQueryClient()`；工厂返回唯一 `{ queryClient, api }` 对，`staleTime: 30_000`、`refetchOnWindowFocus: false`，401/403/404/422 不重试，其余 `failureCount < 2`。无模块级单例，T20 负责创建并接入路由。
- 实现细节（审查注意）：TanStack Query 的 `queryClient.clear()` 会中止进行中的查询，若在 401 `onResponse` 中同步清缓存，调用方会收到 `CancelledError` 而非 401 `ApiRequestError`。因此 `onUnauthorized` 在 401 到达时快照当前所有 queryHash，延迟一个任务（`setTimeout(..., 0)`）后用 `removeQueries({ predicate })` 只移除快照内条目；401 之后新写入的缓存（例如重新登录后的 session）保留，回调本身同步触发。`t04_1_401_clear_is_scoped` 覆盖该作用域，`t04_1_unauthorized_clears_cache_without_retry` 覆盖单条目最终清空。取消用例通过 `queryClient.cancelQueries` 触发真实 Query 取消链（v5 的 `fetchQuery` 不接受外部 AbortSignal），`t04_1_forwards_abort_signal` 另以外部 `AbortController.signal` 直接调用 `raw.GET`，断言注入 fetch 收到的 `Request.signal` 已中止。默认 fetch 包装现透传 `(input, init)` 第二参数。
