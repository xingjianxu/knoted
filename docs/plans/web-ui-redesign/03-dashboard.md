# 03 · 工作概览

**领取条件与文件** 01 后可独立领取。负责 `apps/web/src/features/dashboard/DashboardPage.tsx`、首页路由回调及 `apps/web/tests/tasks/t41.test.tsx`。输入取现有 /dashboard 汇总。

## 现状与信息优先级

现有首卡用四段连续文本展示总量、任务分布和支持格式，随后纵排到期、最近笔记、最近事项。用户查“今天要处理什么”需要先扫过系统统计。设计以到期事项为主栏，每个名称直接打开对象；信息区保留所有现有统计及失效反馈。

| 阅读顺序 | 宽屏 | 窄屏 |
| --- | --- | --- |
| 1 | 工作概览；下方紧凑统计带显示今日到期、未完成、活跃项目、失败任务 | 允许两列或单列换行，长数字完整显示 |
| 2 | 左侧约 60% 展示到期与逾期，行内标题、上海日期、状态；右侧分组最近笔记和最近事项 | 到期列表先出现，最近访问入口随后；短空态不撑满整屏 |
| 3 | 次要统计以标签和值配对呈现笔记、文件总量和四类事项状态，保留失败任务数；现有 dashboard.rs 固定返回 indexing_enabled=false，省去实时启停推断 | 放在主任务之后；移除文件格式介绍 |

## 实施与验证

1. 用 CSS grid 排版，复用 Card、List、ListItem、Badge、Empty。只在有已有去向时让标题可操作；失败任务如提供跳转，应指向现有 /files/jobs，并验证权限与返回路径。
2. 保留 `dateBoundary`、服务端返回顺序及刷新期间屏蔽旧逾期判断。使用现有日期、状态和数据更新时间；0 与读取失败要能区分。用概览布尔值为 false、任务页已有索引记录的样例验证文案一致性，T41 的状态文案断言随之调整。
3. 用「今日有到期且有逾期」「全部为空」「摘要出错后重试」「长标题、多条最近笔记」四组状态验收。桌面首屏看到首个到期对象或明确空态；390px 与键盘能从该行打开正确事项、从最近笔记打开正确笔记。
4. 运行 `pnpm --filter @knoted/web exec vitest run tests/tasks/t41.test.tsx` 和 `pnpm exec playwright test tests/e2e/admin-layout.spec.ts`；交付宽窄屏与空态对照，记录数据刷新后标签变化。共享统计需求超出现有字段时交回总负责人单独评估。
