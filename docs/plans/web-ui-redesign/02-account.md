# 02 · 登录、首次注册、恢复与账号安全

**依赖与范围** 01 后由账号页面 Agent 负责 `apps/web/src/features/auth/{auth-page,security-page}.tsx` 及 T20 测试。入口为 /login、/bootstrap、/recovery、/settings/security。输入为现有 route search、最近验证要求和两套独立分页数据。

## 页面草图与操作次序

| 页面及现状 | 目标首屏 | 动作与反馈 |
| --- | --- | --- |
| 登录与另两种方式共用通用说明和三条同级链接 | 窄栏上方是 Knoted、登录标题，紧接一个全宽「使用 Passkey 登录」；注册、恢复作底部辅助链接 | 启动验证后锁定按钮。取消或失败在操作旁给出可重试反馈；成功返回 safeReturnTo 允许的原地址；现有白名单未列项目路由，保持其回到首页的行为 |
| 首次注册的令牌来源夹在常规说明里 | 标题 → 令牌来源说明 → 一次性令牌 → 凭据名称 → 注册；仅保留离开此流程的链接 | 令牌用密码输入。名称校验位于对应字段；提交中禁止重复启动浏览器认证 |
| 恢复页沿用注册的排版 | 标题后用 Alert 提醒旧凭据与会话将撤销；字段顺序同注册，按钮明确「替换凭据并恢复」 | 后果在提交前可读；失败保留可修正的输入，成功清理令牌。链接可回登录 |
| 安全页把注册表单、凭据、会话连续铺开；部分行横向不换行 | AdminLayout 内单列，约 720px。凭据区标题旁「添加 Passkey」，激活时展开具名表单和五分钟验证提示；会话区突出当前会话及最近使用时间 | 两个列表各自显示翻页、加载、失败和重试；删除与撤销用 ConfirmDialog，错误留在目标对话框 |

## 执行

1. 保留 AuthPage 的 mode 分支和已有 WebAuthn 请求，按模式编排主标题、动作名称、最短说明。公开页使用居中的单列表单，窄屏缩小外围留白并允许键盘弹出后纵向滚动。
2. 安全页使用 List/ListItem；名称和时间在左，操作在右，窄屏操作下移。让「重新验证」直接返回安全页，保留最后一个凭据的保护及服务端拒绝反馈。取消对话框后回到对应记录。
3. 用长中文凭据名、多个会话以及仅有一个凭据的合成记录检查布局。分别模拟凭据读取失败、会话分页读取中，以及浏览器主动取消。验证切页中止 WebAuthn 仪式，撤销当前会话后清缓存并返回登录。
4. 运行 `pnpm --filter @knoted/web exec vitest run tests/tasks/t20.test.tsx` 与 `pnpm exec playwright test tests/e2e/admin-layout.spec.ts`。按总方案提供四个入口的桌面与手机截图、键盘顺序和通过输出；证据使用合成账号，不记录令牌或真实凭据标识。
