# 04 · 笔记目录、写作与版本恢复

实施 Issue [#254](https://github.com/xingjianxu/knoted/issues/254) · [验收与限制](evidence/03-12.md)

**前置**　依赖 [01 基础设计](01-foundation.md) 的内容区、响应式和 mtone 精确发布版本约定。目标是让用户选定一篇笔记后直接写作，并能在原稿仍可恢复的情况下处理保存失败与版本差异。

## 现状与改动位置

在 `/notes` 和 `/notes/$noteId`，目录固定为 `w-64`，与编辑器一起换行。详情在编辑区上方并列六个操作，历史版本打开后排在整个正文、标签和关联表单之后。长文档里，触发「历史版本」与实际预览的位置相隔很远。工具栏还以同等宽度的文字按钮并列正文、三级标题、五种格式及撤销重做。[页面](../../../apps/web/src/features/notes/NotesPage.tsx) · [工具栏](../../../apps/web/src/features/notes/editor/formatting-toolbar.tsx) · [历史面板](../../../apps/web/src/features/notes/HistoryPanel.tsx)

本卡改 `apps/web/src/features/notes/` 下页面、历史、冲突、关联和编辑器工具的呈现，必要时在同一目录拆分目录或文稿标题区。现有 `autosave.ts`、`navigation.ts`、编辑器 schema、文档适配及查询是集成边界。沿用现有路由、应用级导航保护及 AdminLayout.Content。按 [ADR 0002](../../decisions/0002-mtone-ui-ownership.md) 直接使用公共 mtone 控件，BlockNote 继续提供编辑核心。

## 页面与操作

| 场景 | 桌面结构与交互 | 窄屏行为 |
| --- | --- | --- |
| 目录 `/notes` | 左栏顶端「笔记」与「新建根笔记」，下为单选 Tree。首次无数据，仅显示创建入口与空态。有目录而未选中时，右侧保留简短选择提示。目录只有完整加载后才能选取。 | 索引直接显示树，长层级文本换行或截断并保留可访问全名。选中后进入笔记深链。 |
| 写作 `/notes/$noteId` | 左侧目录标出当前节点，主栏按「可编辑标题 → 保存状态和上下文操作 → 格式工具 → 正文」排列。文字版心建议 65–78 个拉丁字符宽，图片和代码可在当前内容栏内扩展。保存并记录历史、查看历史保留可见入口；新建子笔记、移动、复制草稿与删除放在具名操作菜单。 | 顶端「目录」开启 mtone Drawer，正文占满剩余内容宽度。目录关闭后仍是同一编辑实例。工具按段落类型、行内格式、撤销/重做分组，窄屏折行；长代码只在块内横滚。 |
| 标签和资料 | 标题区「标签与关联」开启具名 Drawer。先列已有标签和目标类型、ID，再用展开表单新建/添加标签或添加关联。各自的上一页/下一页贴近各自列表。 | 抽屉按可用宽度布局，按钮自换行。关闭回到入口。加载、错误、重试依附对应分组；写入失败保留输入。 |
| 历史版本 | 标题区打开历史视图，版本列表左、只读快照右，保留标题、版本、时间、原因及「恢复此版本」。在标题下切换到页内历史分区，保持原文编辑器挂载但移出阅读与键盘焦点顺序。分页清空所选快照，恢复需 ConfirmDialog。 | 历史列表 → 选中快照阅读 → 返回版本列表。只读编辑区无写作工具。关闭历史回到原触发器，恢复成功定位当前笔记标题。 |
| 移动、删除与冲突 | 移动用 Dialog 选择根或有效父笔记，删除在 ConfirmDialog 说明有子页时的阻挡。冲突警示紧邻标题，提供「版本与冲突处理」；Dialog 先给复制本地草稿、另存可命名副本，再单列会替换本地内容的加载操作。 | 同一套受控弹层。出错时聚焦错误提示或失败控件，保留重试入口。输入法组合、斜杠菜单、块菜单及图片上传保留现有键盘与选区行为。 |

## 状态与业务约束

- 明确显示未保存、保存中、已保存、失败、冲突、未确认写入以及独立的历史保存失败。普通服务端刷新不能提升本地草稿基础版本；当前树标题只跟随已确认保存。复制、另存副本或关冲突窗口都保留原稿。401 若已有打开的草稿，保留本地编辑会话、停止所有远程续写、可复制并在新标签重新登录后主动按原版本重试。
- 正常切笔记、点主导航、浏览器返回或登出均走已挂载的保存与历史屏障。失败时 URL、树选中项与草稿留在原处。调整抽屉、可见宽度、历史面板和保存反馈不得改变 ProseMirror 实例；仅按现有笔记 ID / reset epoch 规则重建。历史预览使用独立只读 NoteEditor。
- 完整树含跨页节点。移动排除自身、后代，追加到目标父节点末尾；保存与结构变更串行。删除确认先保存内容与历史，有存活子页时解释拒绝；每个成功删除保留独立恢复凭据，原父无效时显式选择恢复到根。网络失败、404 与空目录分别反馈。
- 关联保留原目标 ID；新建标签成功而绑定失败时重试绑定已有 ID。项目、事项、文件与笔记四种目标沿用当前契约。已确认的图片用鉴权资产 ID 渲染，上传重试沿用同一次操作的幂等键。格式工具不抢选区；斜杠建议在中文组合输入期间不插块。[关联](../../../apps/web/src/features/notes/links/NoteAssociations.tsx) · [保存与冲突](../../../apps/web/src/features/notes/autosave.ts) · [现有业务验收](../knoted-v1/evidence/t31-notes-page.md)

## 实施顺序与验收

1. 在真实路由准备无笔记、跨页树、带代码和图片的长正文、多个快照四组数据。记录现有桌面和手机宽度下从树到编辑、从正文到快照的路径。先为「长文中打开历史立即可读，关闭后草稿仍在」添加布局回归用例。
2. 调整目录和标题，保持 NotesPage 与 NotePane 的实例归属。用 mtone Tree、Button、DropdownMenu、Drawer 组合目录与操作，再迁移工具栏。验证折行、Tab 顺序、选区、图片上传失败重试和键盘撤销。
3. 移入关联和历史，保留关联状态及编辑会话，分别验证按需展开、翻页、恢复、关闭焦点。连接 401、409 与删除恢复反馈。更新因控件位置变更而受影响的用例，继续通过真实入口触发所有动作。
4. 从仓库根执行定向用例及 Web 门禁；正常发布验收另按 01 和仓库验证指南执行。

```sh
pnpm --filter @knoted/web exec vitest run tests/tasks/t{27,28,29,30,31,32}.test.tsx
pnpm --filter @knoted/web lint
pnpm --filter @knoted/web typecheck
pnpm --filter @knoted/web test
pnpm --filter @knoted/web build
```
