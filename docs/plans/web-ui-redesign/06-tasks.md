# 06 · 事项清单、看板与单项跟进

**状态**　待实施。依赖 [01 基础设计](01-foundation.md) 的内容区、密度、断点和 mtone 发布版本。用户打开事项区就能浏览待办，切看板可改变状态；从任何深链进入单项后，直接处理该项的时间、子事项和跟进记录。

## 现状与改动位置

同一个 TasksPage 先铺开含十个字段的创建表单，再展示视图、筛选、翻页和结果，最后才挂载选中事项的编辑表单、跟进时间线与子事项创建表单。打开一条已有事项时，多个相同字段在不同任务上下文中重复出现。看板在中屏以上直接四等分；列表或看板在首次加载时传入空数组，容易同时呈现读取提示与空态。[页面组合](../../../apps/web/src/features/tasks/TasksPage.tsx) · [表单](../../../apps/web/src/features/tasks/TaskForm.tsx) · [看板](../../../apps/web/src/features/tasks/board/TaskBoard.tsx)

改动限定于 `apps/web/src/features/tasks/` 的页面、列表、表单、子事项、看板卡和时间线呈现，及 `apps/web/tests/tasks/t39.test.tsx`、`t40.test.tsx` 和受影响的浏览器验收。项目选项、日期转换、Query 和路由保护沿用现行服务；01 负责 AdminLayout。新界面直接消费 mtone 的 Segmented、Select、Dialog、FormField、List、Timeline、ConfirmDialog。看板列及其状态操作继续由 Knoted 组合，避免另造通用拖放系统。

## 页面与操作

| 场景 | 桌面结构 | 窄屏与焦点 |
| --- | --- | --- |
| `/tasks` 清单 | 首行「事项」和「新建事项」。下一行 Segmented 切换列表/看板，之后是归档和项目筛选及刷新。清单每行以标题作为详情入口，随后为状态、所属项目或独立事项、优先级、截止日期；子事项与归档保留文字标识。页尾只显示当前结果的前/后页。 | 视图切换可见，筛选可换行。每条显示标题和截止信息，其次是状态和项目；无截止时留空或用可读占位。表头隐藏后的字段仍有可访问名称。 |
| `/tasks` 看板模式 | 同一页数据依次放入待开始、进行中、已完成、已取消四列；列头用文本说明状态。如展示数量，标明仅计本页。卡片显示标题、项目和可用截止信息。保留拖入列与 Alt+左右键修改状态的提示和路径。 | 当内容区放不下四列时按状态纵向分组；触屏可通过卡片上的「更改状态」选择目标列，调用与拖放同一操作。键盘移列后把焦点留在该卡；后续刷新不夺焦点。 |
| 新建顶层/子事项 | 主按钮开 Dialog；顶部标题/说明，以下分「状态与优先级」「项目与父事项」「开始/截止」三组，保存区贴近表单。子项从父事项的「新建子事项」打开，预置并锁定该父项。成功后关窗、刷新来源列表，失败保留输入。 | 单栏并以配对字段表示日期和可选时间。服务器字段错误挂靠对应输入；软键盘下仍能滚到保存。关闭后回到本次发起按钮。 |
| `/tasks/$taskId` 详情 | 01 的 Header 提供「返回事项」，内容从标题、状态、编辑和更多操作开始；主栏为说明、子事项（仅顶层）、跟进时间线，辅栏以 PropertyList 呈现所属项目、父事项、优先级、时间与版本。编辑打开当前事项的 TaskForm；归档与确认删除在更多操作中。 | 返回后保留来源是清单还是看板及筛选、游标。直接深链以默认清单为返回目的。详情依次为标题、属性、说明、子项、跟进；不能编辑时在标题附近给出原因，读取仍可用。 |
| 子事项 | 区标题附「新建子事项」，当前页列出包括已归档的子项，页尾翻页。选择子项进入该项自己的深链；子项详情显示可返回的父事项。 | 行标题可换行，列表与新建按钮不重复同一套表单。 |
| 跟进与修订 | Timeline 区首「添加跟进」展开输入，记录按服务端顺序列出上海时间、人工跟进/系统事件与正文。只在可写人工记录上提供编辑、删除；修订由「查看修订」按需展开，有自己的历史游标。 | 长段落保留换行；就地编辑、版本冲突和重新读取放在对应记录下。系统事件只读，删除项清晰标记，普通时间线不泄露旧正文。 |

## 状态与业务约束

- 列表首次请求和失败分别显示加载或带重试的错误；成功返回空数组才显示 Empty。切归档/项目筛选重置游标，列表与看板共用同一筛选和页。切换视图不伪造总量。父项、项目或选项未加载、不可读、已归档或已删除时，受影响的写操作保持禁用。
- 整套移列入口复用同一带 `expected_version` 的写请求、单飞和本地预览。期间锁定视图、筛选、分页和重复拖动；409 撤回到原列并显示原因，已确认成功后即使刷新失败也保留新列。父项进入已完成状态要求所有存活子项均已完成或取消（含已归档子项）；新增、移入或重开子项也受这一条件约束，由服务端裁定。归档或祖先不可写时禁止移列。
- 同一 TaskForm 负责顶层、项目、单层子项的校验，子项继承父项项目。跟随服务端父子、归档与删除门槛，不引入二级子项。删除有子事项会被拒绝；确认时说明进回收站、30 天内可恢复，取消不写。父或项目归档不能通过单项取消归档绕开。
- 起止按 `Asia/Shanghai`，保留纯日期与精确到分钟两种输入。开始纯日期取当日零点，截止纯日期取次日零点；单填时间、非法/重复本地时间、倒置区间均反馈到字段。清空关系或时间要显式发 null。[日期转换](../../../apps/web/src/features/tasks/dates.ts) · [业务表单测试](../../../apps/web/tests/tasks/t39.test.tsx)
- 草稿绑定事项 ID 与开始编辑时的基础版本。409 保留可手动复制的草稿，显式刷新服务端及祖先状态成功后再按新版本重试。刷新失败继续禁止覆盖；关闭弹层前让用户能取消放弃输入。人工跟进沿用 1–10000 字符及独立版本，编辑期间 Query 刷新不得推进其草稿版本。人工跟进删除成功立即隐藏旧正文，系统事件始终只读。迟到的活动/修订响应不得进入另一事项。[跟进组件](../../../apps/web/src/features/tasks/timeline/ActivityTimeline.tsx) · [看板与时间线测试](../../../apps/web/tests/tasks/t40.test.tsx)

## 实施顺序与验收

1. 预置四状态、跨页、独立/项目、单层父子、含人工/系统/已删除记录的数据。先补清单首次加载不显示空态、手机点选移列能回滚、切详情后能返回原视图的回归测试。
2. 依现有 taskId 分离集合与详情，保留 TasksPage 的视图与游标状态。把创建入口移到页首，统一 TaskForm 的弹层形态；完成读写状态与日期验证后再移动子事项创建入口。
3. 改造列表和看板，指针、触屏、键盘各验证一次同一张卡。用延迟响应、409、PATCH 成功但后续 GET 失败三种夹具检查单次请求、焦点和最终列。
4. 重排详情、子项、时间线和就地修订，把归档只读与版本冲突放到当前操作附近。验证修改后回读、撤销输入、防止跨项复用草稿及被删除内容隐藏。调整旧断言时保留真实路由、网络与版本断言。
5. 从根目录运行下列命令，并在真实 Chromium 对桌面与手机宽度执行清单→看板→详情→返回。

```sh
pnpm --filter @knoted/web exec vitest run tests/tasks/t{39,40}.test.tsx
pnpm --filter @knoted/web lint
pnpm --filter @knoted/web typecheck
pnpm --filter @knoted/web test
pnpm --filter @knoted/web build
```
