# Knoted Web 全站重设计方案

2026-11-19 · 基线 `8b114cd` · [方案跟踪 #247](https://github.com/xingjianxu/knoted/issues/247)

**目标** 保留 AdminLayout，让人进入概览就看到待处理事项，进入详情就看到选中的对象，打开笔记或问答就能开始阅读和输入。全部实施卡状态均为**待执行**。当前交付是设计与任务分工。

## 从现状到设计

认证后的页面已共享侧栏、顶栏、滚动内容区；影响体验的主要差异出现在内容区。概览用多段文本承载统计；项目、事项、文件在选中对象后继续渲染上方名册；笔记树、会话列表和编辑菜单同时占用窄屏空间；搜索的高级条件在结果前常驻。具体代码位置、业务约束与调整次序见对应卡。[浏览器核查记录](audit.md)

建议以现有暖白、白色和低饱和青绿为基调。高饱和度留给错误、风险和关键状态，所有状态都有文字。全站保持紧凑控件，但为编辑与阅读留出行宽与段距。每页有一个主标题，每个活动区域保留一个明显主操作；同一对象无需重复「详情」「打开」和标题。用对齐与间距分组，边框用于划清可操作区域。信息具有实际跳转或操作时才显示交互样式。

| 页面类型 | 用户进入后先看到 | 按需出现 |
| --- | --- | --- |
| 集合（项目、事项、文件、搜索） | 页名与主操作 → 当前检索/筛选 → 行标题、状态、必要元信息 → 游标导航 | 新建表单、低频筛选、次要元数据 |
| 对象详情 | 返回所属集合 → 对象标题、状态与主要动作 → 正文、预览或跟进 | 编辑、关联维护、技术属性、危险操作确认 |
| 工作区（笔记、问答） | 当前文稿或会话占主栏；宽屏可并列局部目录 | 窄屏通过具名入口选对象；历史、引用、冲突按当前上下文展示 |
| 单一任务（认证、错误页） | 当前动作、必要输入、反馈 | 替代入口放在主操作之后，恢复账号的后果在提交前可见 |

1. **先做 01。** 核对 npm、锁版、公开类型与现有主题，然后定稿标题、边距、返回上下文和游标导航的样例。公共文件、依赖版本由该卡独占。
2. **优先验证 04、06，再核对 03。** 先消除笔记窄屏挤压和事项详情被长列表推离首屏的问题，再用概览检验信息层级。02、05、07–11 在 01 就绪后可按模块并行。05/06 共用的事项列表由 06 负责，05 消费现有接口；07/08 各自维护文件域与 jobs 子目录。共享测试文件由集成 Agent 协调，勿同时编辑。
3. **最后完成 12。** 各卡在独立 worktree 内实施，PR 关联实施 Issue，写明对照截图、操作步骤、测试命令与结果。总负责人读 diff、独立审查、按仓库门禁合并、验证主线并清理。每卡作者对本域的失败、冲突、空态、移动端与键盘负责，12 额外负责跨域回归。

## mtone 与业务边界

检查当日 `npm view @bixlab/mtone dist-tags --json` 返回 `latest: 0.6.0`，与 apps/web/package.json、pnpm-lock.yaml 一致。发行包 dist/index.d.ts 已导出本方案使用的 AdminLayout、List、Tree、Timeline、Tabs、Drawer、Dialog、FilterBar、Empty、Result 等。保留全站 mtone Provider、公开 CSS、直接导入；具体 props 在开卡时按锁版核对。[npm 发行元数据](https://registry.npmjs.org/@bixlab%2fmtone/latest) · [组件归属 ADR](../../decisions/0002-mtone-ui-ownership.md)

页面复用现有字段、请求、权限、URL 与深链。游标列表只显示能从当前响应得知的范围。进一步筛选或汇总需要新 API、持久偏好需要新存储时，另行评估。确有通用组件缺口时，执行仓库 [mtone 需求交接](../../../.agents/skills/mtone-component-request/SKILL.md)，提供完整提示词并关联上游 Issue；其余卡继续。依赖风险、验证和上游处置参见 [UI 指南](../../development/ui-mtone.md)。

**每卡最低交付** 在 PR 附当前与目标界面相同数据的宽窄屏截图，记录键盘路径、加载/空/错误/恢复结果，并实际运行相应 Vitest 及总体验证命令。现有测试中依赖旧排版的查询可按可访问名称更新，原有业务断言须继续成立。
