# Dev 问答配置实施计划

> **For agentic workers:** Use `superpowers:executing-plans` with TDD and an independent final reviewer.

**目标：** 恢复 dev 的真实 Strata 问答；日常启动/部署不再依赖手工重复 export。

**设计（会话已确认）：** 复用实例现有的 `deploy.env` 和运行变量白名单。启动与部署读取同一份纯数据，不直接执行文件；保留显式环境覆盖。与写死宿主地址相比，这也支持隔离实例；不新增服务、不改生产和凭据权限。部署前校验启用的本地模型凭据，模型配置改变则完整重载编排，同 SHA 也不跳过；无变更仍按现有策略验证或进程级重启。关联 [#246](https://github.com/xingjianxu/knoted/issues/246)。

## 实施与验收

1. **主 Agent / 恢复 dev（依赖真实宿主）**：确认无活跃问答；保存现有 `deploy.env`，原子补齐三个 `KNOTED_CHAT_LOCAL_*` 非秘密值，从有效的 `strata-clients` 会话带现有能力变量完整重启。检查共享服务 PID 不变，API/intelligence 就绪。临时浏览器会话用空的合成资料范围提交「你好」，验证真实模型、终态和回复非空，撤销测试授权并清理合成条目。
2. **主 Agent / 脚本（同一任务 Worktree）**：补 `tests/pc` 红测：文件仅作数据、缺失/坏行/环境覆盖、凭据不可读；部署同 SHA 改模型、迁移不变但模型变更、错误不停止旧实例、部署后确认已应用新模型。提取共用白名单和加载器；`service.sh` 渲染及启动前加载，复用模型验证与渲染做配置差异判定；`deploy-dev.sh` 在判断同 SHA 前比较模型配置，需要时完整重载并验证准备结果。保持原有迁移和无变更发布语义。更新开发部署文档，运行 Bash 语法检查、`pnpm test:pc` 与合并门禁。
3. **主 Agent + 独立审查 / 集成**：依 ADR 0003/0005，只影响 dev；审核脚本和回退语义并按仓库流程合入。主线用真实 `pnpm pc up -D`（不显式传模型设置）和 `pnpm deploy:dev` 验收，核对聊天配置与实际生成。若有前置条件或验收阻塞则保留成果、记录实际状态。

**审查重点：** 绝不将凭据内容持久化或输出；文件不 `source`；配置或凭据错误不切换部署指针；未变化路径不产生不必要的停机；不要把模型错误误归因为主 API readiness。
