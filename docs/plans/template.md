# 任务标题实施计划

> 执行方式：拆分后的可独立交付项登记为 GitHub Issue 与 `docs/tasks/<编号>.md`，按直接前置依赖依次推进，不提前标记完成。

- Goal: 可验证目标
- Issue / authorization: 真实 Issue 或直接人工请求及授权范围
- Design / ADR: 方案依据和已确认决策；无则说明
- Scope / exclusions: 修改范围及不涉及的部分
- Baseline: 主线、fork SHA、已知失败
- Native Plan/TODO: 工具名；不可用时本清单为替代

## 文件与接口

列出新增、修改、保留的准确路径，每个接口的输入、输出和依赖。不要只写“相关文件”。

## 任务与依赖

| 任务 | 执行者 | 输入 / 依赖 | 输出 / 文件范围 | Worktree / 分支 | 验收 / 测试命令 | 可并行 |
|---|---|---|---|---|---|---|

逐项填完再实施。共享核心文件的任务串行，读审查可并行。委派补充 [契约](../development/subagent-task-template.md)。

## 风险与人工决策

列出风险、触发信号、应对措施、决策负责人；重要架构、安全策略和不可逆操作等待明确确认。
