# T27–T35 实施与集成计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 完成块式笔记编辑、自动保存与历史页面、标签关联及项目事项后端，逐卡通过验收并合入 master。

**Architecture:** 沿用批准的 v1 requirements/data-and-api 和 ADR 0002；BlockNote 只保留编辑核心，mtone 提供通用 UI，Knoted 实现命令/DTO/草稿适配。后端沿用 AppContext、SQLx 事务、entity_registry、CAS 与 outbox；不引入新服务或存储选型。

**Tech Stack:** Rust 2024/axum/SQLx/PostgreSQL；React/TypeScript/TanStack Query/BlockNote/mtone 0.3.0；Vitest/Playwright。

## 输入与授权

用户直接委派完成 T27–T35，并允许最多同时 3 个 subagent。各卡为独立任务，验收以卡和既有规范为准。基线 master/origin/master 均为 249db1953dc2dbff043a97340c40de5b6edb4b5b，主工作区干净；其他 HTTPS Worktree 保留。

## Global Constraints

- 所有修改在主根 `.worktrees/<task>` 的独立分支；不写主检出、不嵌套、不删除其他任务成果。
- BlockNote 关闭默认 UI，不引入 Mantine/shadcn；通用 UI 只使用已发布 mtone 公开能力，不包装 Base UI、不复制/patch 上游。
- 业务状态、版本、限额、错误码以既有契约为准；浏览器 HTTP 先登记 OpenAPI，再实现并生成客户端。
- 不做生产部署、破坏性数据库操作、性能测试、Android、同步、用户导出。重大新架构或不可逆操作单独确认。
- 凭据不得进入提交、文档、Issue、PR、日志。临时文件仅 `/data/knoted-dev/tasks/<task-id>/`。
- 子 Agent 不自行合并主线、不派生子 Agent；主 Agent 独立审查、复跑测试、串行处理共享注册/锁文件与生成文件的集成。

## 方案与分工

既有规范已选择 BlockNote + mtone、单体模块 + API/Worker；本次直接实施这些已授权设计，不重新选择技术。整体合为一个大 PR 会失去逐卡验收，故每卡独立分支和 PR。T27–T31 按编辑器依赖串行，T32–T35 按后端依赖串行；两条线文件和接口独立时可并行实施，合并、部署和共享文件集成由主 Agent 串行完成。最多 3 个 subagent（实施/只读研究/独立审查）。
