- 基线：主线 `e18ae55b6437134a170d2c5b161d201170d9cdc8`
- Issue：[#185](https://github.com/xingjianxu/knoted/issues/185)

## 目标

把统一可检索投影可靠写入 Meilisearch：每 source/version 一个稳定文档键，投影、任务与 outbox 同事务；只有 Meilisearch 任务 `succeeded` 才算发布，仅 `enqueued`/`processing` 返回可重试失败；旧版本由后台清理任务删除，可见性不依赖删除速度。

## 契约

- `publish_fulltext(ctx, SourceDocument) -> Publication`：校验 → 事务内写 `source_documents`、`fulltext_publications` 与 `fulltext.publish` 任务（`jobs::enqueue` 同时写 outbox）。
- `get_publication(ctx, GetPublication) -> Option<Publication>`：按 source/version（缺省当前版本）读取发布状态与 Meili task id。
- Worker `fulltext.publish`：确保索引与设置 → 提交文档并落库 task id → 轮询任务 → `succeeded` 才标记 `published`（同时把旧版本发布标记 `superseded` 并入队 `fulltext.cleanup`）。
- Worker `fulltext.cleanup`：按文档键批量删除旧版本文档，成功后删除旧投影与发布记录。
- 状态机：`pending → submitted（task id 落库）→ published | failed`，另有 `superseded`；`published_at` 与状态同事务写入。

## 存储

`0016_t53_fulltext.sql`（新增未应用迁移）：

- `source_documents`：`source_type/source_id/source_version` 唯一，当前版本用部分唯一索引（`superseded_at IS NULL`）保证同一来源只有一份当前投影；`title/body/project_id/tags/archived/deleted/path/format/updated_at` 覆盖 T54 的过滤与排序需求。
- `fulltext_publications`：`(engine,index_uid,document_key)` 唯一，`document_key = <type>_<uuid simple>_v<version>`（Meilisearch 只接受字母数字、`-`、`_`），因此重试是同一文档的 upsert，不产生重复可见项。

## Meilisearch 设置

- `primaryKey = id`
- `searchableAttributes = [title, body]`
- `filterableAttributes = [source_type, source_id, source_version, project_id, tags, archived, deleted, path, format]`
- `sortableAttributes = [updated_at, version]`
- 中文分词依赖 charabia 全语言 tokenizer；nixpkgs 包用 `buildNoDefaultFeatures = true`，本机用官方 1.56.1 release 二进制验证（任务区 `/data/knoted-dev/tasks/t53/meili/`），已实测长中文句子中「知识管理/中文词语/检索」等词命中。
