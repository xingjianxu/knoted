# T37 事项归档和回收站 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成单张 T37 的事项生命周期、30 天安全清理及既有写入口的只读保护。

**Architecture:** 复用当前 Task DTO、DomainError、关系 advisory lock → 跨表 UUID 行锁 → CAS → durable task.changed outbox 的事务协议；不引入存储契约、归档级联批次或新检索模块。归档保持可读，删除立即通过 PG 当前状态不可见。Worker 在既有进程增加独立维护循环，不影响历史补存。

**Tech Stack:** Rust 2024、SQLx/PostgreSQL、axum、tokio；固定 SHA 产物与 pcwrap 测试实例。

**Spec:** [T37](knoted-v1/tasks/T37.md)、[需求](knoted-v1/requirements.md)、[数据/API](knoted-v1/data-and-api.md)、[检索](knoted-v1/indexing-and-rag.md)、`api/openapi.yaml`；本页「已确认设计」为本会话用户确认的规则补足。

## 已确认设计

2026-11-17 用户在结构化问题中选择「最小兼容方案 (Recommended)」，确认下列方案；原始目标为「完成T37任务卡」。

- **选项 A（已选）**：只改变所请求事项的 archive/unarchive；不限终态，不级联子事项，不使用项目 archive_batch_id 表达父子批次。父/项目只读时，子事项正文、跟进、标签和关联一律禁止写。优点是保持既有 API/存储协议且可独立验收。
- **选项 B（未选）**：父子级联归档并按批次撤销；需要额外批次语义/存储设计，不适合本卡最小兼容范围。
- restore 保留当前 parent/project；父缺失/已删/归档、父非顶层、项目不可写、继承不一致均 409。先恢复父，不自动移根/恢复父/重开 done 父；恢复须重验 T35 终态约束。
- 30 天是清理资格线，不是 restore 硬截止；未物理清理仍可恢复。清理只覆盖 task，含其 activities/revisions 和 task_tags；保留 entity_registry、共享 tags、失效 entity_links、未发布 outbox，不扩展 notes/projects 清理。
- purge 先过期叶子，再父；任何尚存子行均阻止父清理，不提前删未满期子，不置空 FK。永久回收事项时一并回收其系统/人工时间线，不影响共享实体身份或关联快照。
- 范围补充是封闭 T37 的现有写入口与模块接线：tasks service/repository、activities guard、links visibility guard、API tasks routes、Worker 注册/main、测试及证据文档；不是新业务模块。

## Global Constraints

- 只领取 T37；不实现 T38/T42 UI、T53/T57 搜索/RAG；无源目录写入、生产操作、性能测试或导出。
- 现有 HTTP：POST /tasks/{taskId}/archive、/unarchive、/restore；body 仅 expected_version；返回 Task + ETag。DELETE 保持 query expected_version。
- 生命周期同事务递增 version、更新状态并追加 task.changed；归档仍可检索，删除必须以 PG 当前 deleted 状态立即失效，不能依赖异步引擎删速度；当前无检索投影，不能声称搜索端到端验收。
- 不修改已应用迁移；不需要迁移则不新增。保留 registry 稳定身份、资料关联失效目标、共享 tags 与 durable outbox。
- ADR 0003/0004/0005：pcwrap API/Worker、宿主数据库、共享 Caddy；不修改 host 仓库。
- 所有修改在主根 `.worktrees/` 的独立分支；一个实施 Agent，串行修改；主 Agent 负责锁/API生成文件、审查、集成、验证、部署和清理。
- 每次提交前实际读取 git-commit Skill，不绕 hooks；中文摘要/正文、英文 type/scope/footer。

## Review Focus

1. 父归档/项目归档经正文以外的 activities/tag/link 写入口绕过；输入 read/write 模式须分离，读仍允许。
2. restore 非终态子到 done 父，或回收站子已经随父迁移项目；必须重验当前关系和最终状态。
3. 父先过期但子未满 30 天；不得因父清理级联缩短子保留期，叶子到期再处理父。
4. outbox/删除触发失败、CAS 竞争和 purge/restore 交错；失败回滚状态、版本和依赖表，锁序不产生死锁。
5. 项目批次归档撤销不得取消手动事项归档；保留 registry 与 link 的失效目标而非级联删除用户资料关系。
