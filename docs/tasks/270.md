## 交付目标

参考 `../dek` 的 GitHub Issue 协作方式重构 Knoted 开发流程：使用 GitHub 原生 Issue Type（`Feature`/`Bug`/`Task`）、原生 `blocked-by` 依赖、`docs/tasks/<编号>.md` 任务卡索引、`gh issue develop` 关联分支与主仓库 `.worktrees/<编号>-<slug>` 隔离工作区、Issue 评论记录进度与验收，同时引入 AI 提交署名规范与 `.githooks/prepare-commit-msg` 钩子，并为现有 15 个 open Issue 补设原生 Issue Type。

## 范围与落点

- 核心规则与入口：`AGENTS.md`、`README.md`、`docs/tasks/README.md`、`docs/tasks/270.md`、`docs/plans/README.md`。

- 远端元数据：为现有 15 个 open Issue 补设原生 Issue Type（`Bug`/`Task`），不增删仓库标签定义，不改动 ruleset 或仓库设置。
