# #265 匿名直达笔记页面时显示加载错误而非登录

- [GitHub Issue #265](https://github.com/xingjianxu/knoted/issues/265) 的类型为 Bug，直接前置为无。
- 分支为 `issue-265-notes-auth-redirect`，worktree 为 `.worktrees/265-notes-auth-redirect`。
- 相关文档 [T20 登录与应用外壳](../plans/knoted-v1/evidence/t20.md)、[架构现状](../architecture/README.md)。

## 实施步骤

1. 在 Chromium 用实际 JSON 错误契约模拟匿名会话请求，定位笔记路由收到的 `CancelledError`。客户端在读取 401 响应体前通知缓存清理，后续任务可能先于错误解析而移除会话查询。
2. 在 `apps/web/src/features/auth/auth.ts` 让路由门禁直接持有会话请求，路由切换时按其信号中止。收到 401 响应头时仍登记和清理当时的查询缓存，会话请求继续读取错误并决定是否回跳。
3. 在 `tests/e2e/redesign.spec.ts` 通过浏览器首载验证会话缺失、服务不可用与网络断开，运行 T04、T20 和 T31 检查缓存、登录回跳与已初始化草稿。用延迟的 401 响应体验证旧查询清理和新查询保留。

## 验证场景与预期结果

- 匿名直达笔记列表或合法笔记详情时，会话接口返回 401，显示可用的 Passkey 登录入口，回跳地址指向原笔记路径，页面未请求笔记数据。
- 会话接口返回 503 或连接失败时，停留在笔记地址并显示可重试的加载错误。
- 已初始化笔记遇到 401 继续保护本地草稿。登录回跳沿用站内路径校验。
