## 实施步骤

1. 扩充 `tests/e2e/redesign.spec.ts` 的原生 Chromium 拖放测试，暂停目录请求以复现抖动，再覆盖嵌套、拖出和图标。
2. 在 `NotesPage.tsx` 使用 mtone Tree 的落点信息和 `moveTreeItem` 即时显示新的目录，复用笔记移动和草稿保存流程。已有目录时保持树的布局稳定。
3. 核对移动失败、活动编辑器会话和服务端确认的顺序，运行 Web 本地检查并独立审查。

## 验证场景与预期结果

- 放手后立刻显示新顺序，目录重新读取时树的顶部位置稳定。保存失败显示错误并恢复已确认顺序，可再次拖动。
- 拖到行中间会成为目标笔记的最后一个子笔记并展开目标。拖到行上缘或下缘会进入目标所在的同级列表，包括根目录。移动保留子树，禁止原位操作和循环关系。
- 所有笔记显示文档图标，已有子笔记时仍可展开和收起。
- 当前笔记移动前先保存草稿与历史，移动后保留当前编辑器。刷新后保留服务器确认的层级和顺序。
