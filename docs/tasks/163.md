# #163 tech-debt(api-client): 为非 2xx 错误体解析建立有界读取

- [GitHub Issue #163](https://github.com/xingjianxu/knoted/issues/163) 的类型为 Task，直接前置为无。
- 分支为 `issue-163-bound-api-error-body`，worktree 为 `.worktrees/163-bound-api-error-body`。
- 错误信封见 [OpenAPI](../../api/openapi.yaml)，响应头的请求编号来自[服务端中间件](../../crates/knoted-api/src/middleware/request_id.rs)。

## 实施与验收

1. 在 `packages/api-client/src/errors.ts` 从原始错误流读取最多 64 KiB 用于 JSON 解码，给错误码、字段校验和版本冲突诊断留出空间。按读取到的字节计量，支持分块 UTF-8 文本和缺失或不准确的长度头。
2. 超过预算或请求中止时取消流、释放 reader。无效、截断或读取失败的正文降级为 HTTP 状态错误，保留响应头中的请求编号。合法信封继续报告业务错误码、消息和附加字段。
3. 在 `packages/api-client/src/client.ts` 透传请求的取消信号，401 沿用单次回调。用 [T04 客户端测试](../../apps/web/tests/tasks/t04.test.tsx) 验证等于预算、超限、流失败与读取中止，包括底层取消回执仍未返回的情况。
