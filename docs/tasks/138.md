# #138 test(db): panic 回滚期间 TestDb 同步清理可能死锁

- [GitHub Issue #138](https://github.com/xingjianxu/knoted/issues/138) 的类型为 Bug，直接前置为无。
- 分支为 `issue-138-testdb-panic-cleanup`，worktree 为 `.worktrees/138-testdb-panic-cleanup`。
- 数据库边界见 [ADR 0004](../decisions/0004-database-owned-by-host-user.md) 与[程序测试环境](../development/validation.md#程序测试环境)。

## 实施与验收

1. 在 `crates/knoted-core/tests/t05.rs` 用单线程 Tokio、真实 PostgreSQL 和事务内的解码错误触发 panic。PostgreSQL 查询已取得关系锁，SQLx 的回滚仍等候原运行时推进。回归给数据库锁等待设置期限，并回收失败时遗留的本次 schema。
2. 在 `crates/knoted-core/src/db/testing.rs` 用本次生成的 schema 名标记连接池。同步析构关闭连接池准入，使用独立会话结束同库、同角色、同标记的后端，再删除该 schema。为锁等待和整个后备清理设置期限。
3. 验证 panic 本身能够传播、schema 已删除、持锁后端已退出。另一夹具原有的连接与 schema 应继续可用。
4. 执行 T05 验证显式异步清理、无事务的同步清理以及拒绝非测试库的路径。
