## 实施步骤

1. 先在笔记页测试和 Chromium 夹具覆盖拖动落点、草稿保存、失败反馈与刷新后的顺序。
2. 在 `NotesPage.tsx` 为 Tree 启用 `draggable`、`allowDrop` 和 `onDrop`，将同一父节点的行上缘、下缘换算成移动后的同级索引。
3. 让拖动和「移动到…」共享现有的移动请求、版本校验和目录刷新流程。
4. 运行 Web 本地门禁和 Chromium 回归，由独立审查复核，再按仓库流程合并与部署。

## 验证场景与预期结果

- 桌面鼠标可在根笔记与各自的子笔记列表内向前或向后排序。目录以服务端返回的顺序为准，刷新后保留结果。
- 行中间、跨父节点和原位置的落点不会发起移动请求。通过「移动到…」继续变更父节点。
- 排序当前笔记时先保存草稿和历史，再用新的版本提交；编辑器保留当前实例和选中状态。提交失败时保留已确认的目录顺序并显示错误。
- 详情已读到其他会话更改父节点时，重新读取目录并提示用户在新位置排序。
